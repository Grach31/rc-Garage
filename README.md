# RC Garage 2.0 · Minimal Collection

Визуальный прототип для согласования. Галерея и страницы 10 моделей; поиск,
фильтры, разделы характеристик, компонентов, обслуживания и фотографий.
Ветка: `design/minimal-collection`. Изменений в main и публикации нет.

## Запуск

Нужен Python 3: `python3 -m http.server 4173`, затем открыть
http://localhost:4173. Или `npm start` (Node используется только для команды).
Сборка и установка зависимостей не требуются. Проверка JS: `npm run check`.

## Архитектура

- `index.html`, `styles.css`, `app.js` — статическое приложение без фреймворка.
- `data/collection.json` — каталог и единственный источник сведений.
- `assets/` — фотографии владельца; инструкция в `assets/README.md`.
- `docs/` — снимки главной страницы и страницы модели на компьютере и iPhone.

Новый репозиторий содержал только README. Прежний проект и его подтверждённые
данные не предоставлены. Каталог использует исключительно сведения из задания;
неизвестные поля равны null и отображаются как «Не указано».
Производители самодельных моделей не выводятся из названий настоящих грузовиков.
6S в названии GT не используется как подтверждение параметров аккумулятора.
1:10 указан только для прицепа. Фотографий и демо-изображений нет: используются
явные заглушки «Фото не добавлено».

## Как менять сведения и фото

Редактируйте соответствующую запись JSON. `image` — относительный путь к обложке,
`gallery` — массив путей. Компоненты: `manufacturer`, `model`, `image`,
`specifications` (строка), `notes`. Характеристики в `specifications` модели:
`dimensions`, `weight`, `motor`, `esc`, `servo`, `battery`, `suspension`, `wheels`,
`transmission`. При отсутствии сведений оставляйте null или поле незаполненным.
Программную логику менять не нужно. Предусмотрены ленивая загрузка, фиксированные
пропорции и обработка недоступных фото; оптимизация исходных файлов пока ручная.

## Границы этапа

После визуального утверждения: редактор сведений и компонентов, загрузка и сжатие
фотографий, локальное сохранение (IndexedDB), экспорт/импорт резервной копии с
валидацией, редактируемые тюнинг и журнал обслуживания. Сейчас этих функций нет;
разделы обслуживания показывают пустое состояние. Внешних API, регистрации,
Three.js и сетевых шрифтов нет. Сервер нужен только для раздачи статики.

## GitHub Pages

Архитектура поддерживает Pages: относительные пути и маршруты через hash работают
в подпапке репозитория. После согласования и слияния можно публиковать корень main.
Для private-репозитория Pages требует подходящего платного тарифа GitHub; на Free
понадобится public-репозиторий. Публикация в этом этапе не включена.

## Проверка

Chromium: 10 записей, фильтры, поиск и пустой результат, переходы, возврат,
перезагрузка страницы модели, якоря разделов, неизвестный маршрут, отсутствие
фотографии. Проверка переполнения на ширинах 320, 375, 390, 768 и 1440 px.
Снимки в docs. Это эмуляция размеров экрана, а не проверка на физическом iPhone
или Safari. Финальная оценка композиции с реальными фотографиями — после их
предоставления владельцем.
